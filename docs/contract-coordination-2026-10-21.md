## B02：后台身份提供方与账号绑定

依据：AdminLoginInput/AccountInput 显式开放且标 D02 阻塞；C-01。影响 POST /admin/sessions、后台账号创建绑定，以及 T008/T010/T012/T033 的真实会话。

建议结论：继续失败关闭；用户指定身份交付方后，后端再冻结提供方、凭据交换、可信主体唯一键、绑定/撤销与失败样例。角色永远从后台数据库当前授权读取，不接受登录输入角色。不能将现有开放对象解释为任意密码登录或前端角色选择。

请求示意（不是最终字段）：`POST /admin/sessions {"<提供方交换字段>":"<仓库外测试凭据引用>"}`。成功沿用 `data:{"token":"<仅返回一次>","account":{"id":"synthetic-admin","version":1,"roles":["review_operator"],"active":true}}`；无效凭据401、已撤销会话访问401、有效会话越权403，依赖不可用503，响应不泄漏提供方原文。

兼容性：尚无可验证的最终登录请求；收紧开放对象可能破坏既有消费者，须与两端升级并版本化。需用户决定身份方案及资源方，不自动选择密码或 SSO。解除条件：方案+版本化字段+仓库外测试身份引用+成功/失败/撤销实际服务证据，负责人用户指定身份方/后端。

## B03：扫描状态与首次/重提版本

依据：上传 Asset 仅回 pending；没有本人扫描状态读取操作；VerificationInput 强制 expected_version，但 semantics 的“无现存对象创建不要求版本”与首次申请目标不明确。影响 T011/T013 上传后提交与驳回重提。

建议结论：补本人授权的资产扫描状态读取；版本必须对应明确聚合，禁止以 Me.version、asset version 或固定1替代申请版本。首次不存在申请时建议不传 expected_version；重提使用 GET /me/verification-request 所返回申请版本，具体首次资源模型须核对设计后确认。不要静默修改 required。

提案样例：新增读取操作路径待版本化，`GET /me/student-card-assets/synthetic-asset` → `data:{"asset_id":"synthetic-asset","scan_status":"approved"}`；pending/failed 不允许提交，非本人404且不暴露扫描细节。首次 `POST /me/verification-requests {"student_number":"合成学号","name":"合成姓名","asset_id":"synthetic-asset"}` →202 `data:{"request_id":"synthetic-verification","version":1,"status":"pending"}`。驳回后读取 version=3；重提同接口带 expected_version=3 →202/version=4；旧版2 →409。所有数字仅示意，不承诺每次后台扫描导致何种版本增长。

兼容性：新增 GET 为兼容扩展；取消首次必填/改变命令目标是请求语义变化，需明确版本迁移和新旧客户端适配。真实提交保持关闭。需后端核对设计与两端消费场景，涉及首次聚合取舍交用户；解除需目标模型、扫描枚举、404/409样例和校验通过，不能仅凭建议关闭。

## B04：脱敏列表、读卡授权与审计

依据：GET /admin/identity-reviews 已声明列表无完整姓名学号/学生卡；敏感响应 no-store；C-04。影响 T011/T012 列表、案件详情、读卡和 002-A/B/C、018/019 验收。

建议结论：沿用最小列表投影及签名游标，敏感资料只在当前有权案件详情/卡代理返回；无公开 URL，逐次读卡重新授权并在拥有边界记录业务审计。技术日志不能替代审计。候选 JPEG/PNG、5MiB 尚未确认，不冻结上线参数。

样例：`GET /admin/identity-reviews?limit=20` → `data:{"items":[{"id":"synthetic-case","version":2,"status":"pending","content_version":1}],"next_cursor":null}`；无完整姓名、学号、卡引用。既有卡代理操作 `GET /admin/identity-reviews/{id}/student-card`：授权成功200，Content-Type 为实际验证后的图片类型、Cache-Control:no-store、二进制流；不能返回 JSON下载地址。未知/不可见案件404，角色不符403，失效会话401。换案/撤销角色后再次请求必须拒绝；审计需能核对操作者技术引用、案件引用、动作、结果、时间，不能写图像正文/凭据。

兼容性：列表白名单沿用既有契约；卡接口响应媒体类型与大小需 D02-E/G/H 明确后补 OpenAPI，JSON 客户端须改为受控二进制消费。负责人后端及资源交付方；解除需真实分页、正反授权、撤权、no-store/边界及独立业务审计证据；当前只有提案，未通过。

## B05：案件到业务目标、动作与状态

依据：ModerationCase 缺 kind/id/动作，status 自由字符串；semantics 已规定案件 expected_version、服务端取 content_version/hold_epoch 再校验，ModerationOutcome 区分内容判定与业务结果。影响 T016/T017 判定及限制/解除限制。

建议结论：详情显式返回服务端授权目标及精确目标版本、允许动作；案件判定传案件版本；对内容限制命令传内容目标版本。字段名与动作全集需版本化，不能把案件 UUID 当内容 UUID，也不能从案件入口扩成任意私聊检索。

提案详情 `GET /admin/moderation-tasks/synthetic-case` → `data:{"id":"synthetic-case","version":3,"content_version":2,"body":"合成文本","status":"pending","target":{"kind":"wish","id":"synthetic-wish","version":8},"allowed_actions":["approve","reject"]}`。判定 `POST /admin/moderation-tasks/synthetic-case/decision {"decision":"approved","expected_version":3}` → `data:{"content_decision":"approved","business_outcome":"ready","version":4}`；仅表示通过且未主动公开。旧案件版本或锁后目标/屏障变化409；不信任客户端传旧正文/旧 hold_epoch。限制命令使用该 target 的 kind/id 及 expected_version=8，独立请求 reason，不复用案件版本3。

兼容性：新增 target/actions 为响应扩展，但 0.1.0 additionalProperties=false，须更新 schema 后两端才能接；枚举收紧可能破坏现有合成状态。需后端确认设计映射、两端核对消费；涉及新的处置动作/业务状态交用户决定。解除需状态转移表、权限目标映射、版本/屏障反例及判定/执行样例验证，未解除前真实处置关闭。

## B06：词库基准、条目读取、生效与归档

依据：WordlistInput.entries 有内容但 Wordlist 无条目读取/生效关联；“已有词库创建版本带当前版本”未指出基准对象；C-06。影响 T016/T017 创建、发布、归档展示及扫描生效。

建议结论：优先完整不可变快照而非客户端隐式增量；基准、版本行与每 kind 的生效指针分别明确，发布在事务中比较当前生效基准。该方案尚待设计/用户确认，不能用前端合成实现冻结。归档是替代后历史可读还是禁止读取/手工删除，会影响审计和回溯，必须明确；不新增未经批准删除操作。

提案读取（新增路径待定）`GET /admin/wordlists/synthetic-list` → `data:{"id":"synthetic-list","kind":"school","version":4,"status":"published","entries":["合成词条"],"effective_id":"synthetic-list"}`。创建 `POST /admin/wordlists/versions {"kind":"school","entries":["合成完整新词条"],"expected_version":4}` →201 `data:{"id":"synthetic-next","kind":"school","version":5,"status":"draft"}`；这里4/5仅表达方案，最终必须说明 expected_version 指生效指针还是词库实体，禁止直接照用。发布 `POST /admin/wordlists/synthetic-next/publish {"expected_version":5}` →200/published；并发基准变更409，不能覆盖别人发布。旧版归档不等于物理删除，不承诺重扫历史内容，是否重扫须用户明确。

兼容性：条目读取与生效指针是新增能力；完整快照/基准/归档语义可能破坏两端假设，需协调版本升级，不能仅改示例。负责人后端协调、用户决定业务取舍、运营交 D03。解除需版本对象定义、完整/增量决策、状态/并发样例、正式词库和发布实际生效证据；合成校验不能解除 B11。

## B07：动作、身份标签与会话刷新

依据：Me.allowed_actions 为自由字符串；grade/gender 未定；AdminSessionResult 无到期/续期/me；semantics 要求每次当前授权与会话撤销/到期校验，C-02/C-03。影响 T008–T010/T013–T015。

建议结论：actions 作为服务端当前投影的展示提示，缺失/未知动作失败关闭，后端每次写仍重查授权；建立每动作适用资源映射，不能把账号动作套内容目标。标签可选且受隐藏设置约束已由REQ-003确认；grade/gender具体取值由用户/资料方确认，禁止从两端合成标签猜测。会话 TTL、绝对/滑动到期、是否续期需身份方案和部署策略决定，不自行新增刷新协议。

提案示例：`GET /me` → `data:{"id":"synthetic-student","version":7,"verification":"verified","allowed_actions":["<待冻结动作名>"]}`，不带未确认标签。后台登录仍按B02；已有会话访问受保护操作后若到期/撤销 →401 `UNAUTHENTICATED`，客户端清除；角色变化后当前对象授权不足 →403 `FORBIDDEN`，停止操作；重新登录取得当前 account.roles。是否新增后台会话读取入口和 expires_at 待定，不能把现有无字段解释为永不过期或猜倒计时。

兼容性：冻结动作字符串会改变消费者判断；可选到期字段可兼容新增，但严格 schema 仍须更新；标签枚举和续期策略须同步版本；不能把已确认可选改成必填。负责人用户/身份方决定参数，后端协调两端验证。解除需动作矩阵、标签取值、失效/撤权/刷新策略与真实正反例；保留已有401/403失败关闭，不擅自关闭阻塞。

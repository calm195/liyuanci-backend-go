# 人工认证模块

T011/REQ-002、015、018、019，关联T005/T006/REQ-020。API字段与调用示例维护于共享[人工认证契约](../../docs/contracts/verification.v0.2.0.md)，实施及实际验证记录见[第七阶段](milestones/phase-07.md)。本模块沿用可注入适配器和隔离验证，不执行跨端联调。

`verification.New`不接管池或供应商生命周期，分别以identity_maintenance学生池和admin_api审核池创建实例，显式注入Codec、identity.Store的事务内Binder、学校Rules、Objects.Open、Command配置、独立ReceiptKey和图片字节上限。`httpapi.RegisterVerification`注册申请/本人状态、后台队列/详情/学生卡/决定六个操作。普通server、探针worker均不自动装配合成服务。学生会话的VerificationRequests开关仅在路由就绪时显式开启；未认证/驳回且未受限时才提示申请动作。

service负责申请/重提、加密和审核业务；repository负责GORM查询、锁后会话/角色/生命周期复核和访问审计；read负责最小本人状态、签名分页、详情与原卡的授权/内存生命周期；HTTP处理严格JSON、请求版本、Bearer/幂等头及状态码。没有明文临时文件、公共图片URL或列表身份字段。姓名/学号、原因/建议分别受输入资源上限约束，详见共享说明，学校规则仍由外部适配器决定。

申请材料绑定identity_review用途、随机申请ID和当前申请版本加密。首次无版本，已有rejected记录必须提供申请版本；pending和approved不得用新键重提。重提复用ID、递增版本并替换密文，清空旧意见。按REQ-002注册即绑定学号：申请同一根事务写学号信封及当前/上一代唯一检索占用；驳回修正时先查新值再原子替换密文和双代占用，失败保留旧绑定。审核通过时再次核验学号绑定，写姓名信封、账号verified、决定及审计。驳回记录原因/建议并更新账号rejected，方便修正学号。已通过认证的学号不允许通过该入口改号。回执使用独立HMAC摘要，只返回当前最小结果，重放仍鉴权。

身份全局锁先于后台主体→账号→资产→申请，复用既有双代轮换串行边界；BindStudentNumber要求调用者已有根事务和全局锁，禁止开启独立绑定事务造成半个认证或反向锁。KMS/HMAC在短事务内执行，必须响应context并限制供应商超时；没有把未配置的真实密钥系统宣称完成。

后台队列只含active账号pending申请，UUID升序，limit最大50，游标绑定后台账号及队列并签名，不能跨账号复用。详情访问成功与access_audits一起提交；决定审计失败使整个变更回滚。原卡先授权、读取当前对象引用，再在锁外打开精确私有对象版本、有界读取密文、验证整图；再次持锁复核会话/角色、账号生命周期、申请/资产版本，提交访问留迹后才返回规范化PNG。明文在HTTP写出后清零；供应商失败、注销晚到或审计失败不输出图片。失败请求以安全完成日志记录，不把技术日志当成denied/failed业务访问审计条目。

显式迁移0011只增加待审密文与修改建议，保留历史空材料记录，不伪造其可审核能力；这些历史记录不进新队列，不能通过新审核。非空材料时拒绝破坏性回退，回退先锁表。正常字段由独立实体维护，CHECK/中文注释/回退保护由版本SQL维护，普通启动不执行DDL。资源行锁仅增加资产version列UPDATE权限，不允许审核池改对象key或扫描状态。

真实外部KMS、学校规则、私有桶执行身份、业务API/worker进程装配、生产期限/限额/保留及对象物理清理仍缺；本次不改变独立探针worker或MQ运输，不宣称领域MQ闭环、生产或跨端验收完成。

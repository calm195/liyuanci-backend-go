2026-10-21；T007/T008/T011，REQ-002、014、015、018、019、020。承接第五至第七阶段已实现的身份、上传扫描和人工认证模块，按用户“ 不考虑联调测试，完成可开发内容 ”的指令完成独立应用装配。没有修改共享审批/需求/设计、共享契约、数据库结构及普通启动脚本，提交按用户后续指令分模块执行；未推送或部署。

## 已实现范围与职责

internal/studentapi.New 构造学生身份、学生卡和独立学生/后台两套人工认证服务，在全部构造成功后返回包含十四路由的 Engine。学生和后台审核必须使用不同底层池；会话/学生卡/认证回执密钥不得复用，审核图片预算须覆盖上传上限。Identity 与 Objects 分别复用登录/学号绑定和私有写入/精确版本读取依赖。构造不访问外部供应商、不执行 SQL 或 DDL、不创建默认账号，Ready 必须显式注入。Me 动作提示只在完整应用装配内开启，不修改调用方配置。

internal/cardworker.Open 接入既有 transportmq 的实际生产/订阅客户端、durable.Relay 和学生卡 Consume/ProcessNext，完成可注入领域 worker 的应用生命周期。固定学生卡事件；发件箱转发与数据库补偿独立单线程轮询，每轮独立超时，结束后等待，失败/panic 可继续调度。MQ 并发由独立配置约束。启动失败释放已创建客户端；关闭先取消调度、停止消费并等在途请求、等待轮询退出，再关闭生产者。并发重复 Close 不重复释放，关闭错误安全化并继续清理其余资源。数据库和供应商由外层拥有，调用结束后才允许关闭。

关键取舍：保持数据库持久源为权威，调度只调用已有领域复核而不重建业务；数据库补偿独立于消息唤醒，避免 ACK Deferred 后失去后续推进。技术参数全部显式提供，不臆造生产 TTL 或扫描政策。中文结构化日志只含 operation/result/duration，不输出供应商错误正文。

接入顺序、模块职责及资源所有权详见[应用装配说明](../application-assembly.md)，README 四部分内同步目录及启动方式。

## 验证与边界

最终代码与文档执行 make fmt、make check（只读格式检查、go vet ./...、go test -race -cover ./...）、make build 及 git diff --check 均退出 0。cardworker 测试 1.553s/80.0%，studentapi 测试 1.715s/88.1%；未修改依赖，无需 go mod tidy。开发期间首次构建提示模块缓存写入被沙箱拒绝，后续 vet 也曾因构建缓存访问退出失败，允许所需缓存访问后上述完整检查通过，不把受限尝试当成功证据。

单元测试不启动中间件，学生 API 测试禁用数据库 Ping，只核验构造与未授权路径；供应商夹具不提供业务成功。调度测试验证失败/panic 恢复、超时、空闲取消、成功日志、等待在途、并发关闭及错误继续清理。缺真实环境的既有集成测试继续 skip，不能计为真实链路通过。

用户本轮明确不考虑联调测试，因此未运行 PG/Redis/RocketMQ、跨端、微信、对象存储或扫描供应商联调。没有新增数据库操作或 Broker 机制变更。cmd/server 与原探针 cmd/worker 未切换到新应用；真实供应商、仓库外资源及执行身份验权/就绪检查、进程配置接线、异常待办管理、物理清理与生产验收仍未交付。本阶段只完成应用装配库的可开发子范围，不声称整个后端或 T007/T008/T011 已完成。

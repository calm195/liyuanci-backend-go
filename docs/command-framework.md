# 数据库事务与授权命令入口

T006；REQ-004、005、006、007、014、016、018；授权关联 REQ-002、019、020。当前是供后续领域服务调用的库，未装配业务 HTTP 路由，不签发登录令牌。依赖、实测和未完成范围见 [第三阶段](milestones/phase-03.md)。

## 调用与职责

装配方通过 `command.New(db, logger, config)` 显式注入根 GORM 连接、zap、总超时、锁等待上限、最多 1–10 次尝试及正回执保留期；不接收外部事务。参数是技术配置，尚无生产保留期验收。HTTP 层验证 Bearer/Idempotency-Key、请求长度、DTO 和字段，映射稳定错误；本库不决定最终 401/403/404 隐藏策略。

服务端固定 `Definition` 的命令名、HTTP 方法、已解析对象的规范路径、学生/后台命名空间、权限、必填版本字段和回调。策略不可从请求反序列化，装配后不可并发修改；路径不含 query、fragment、百分号或非规范片段。创建命令可以无版本字段，更新命令应通过 `RequiredExpectations` 声明必填字段；调用方负责把字段绑定到该路由的正确目标，不能只声明名称却绑定其他对象。

| 回调 | 责任 |
| --- | --- |
| Discover | 使用所给只读连接发现完整账号/后台主体/资源集合；只返回技术引用。重复调用的业务发现逻辑必须一致 |
| Authorize | 持锁后复核当前对象的访问资格、参与者、拉黑/案件/隐私屏障等领域权限；也在重放时运行，不能要求首次业务状态仍成立 |
| Apply | 仅通过 Tx.DB 的当前事务执行业务变更；需要外部工作时只写同事务的工作/发件箱记录。返回 UUID 技术引用 |
| Resolve | 查询并校验结果引用当前仍可访问；首次执行和重放均调用，不返回历史正文快照 |

`Tx.DB()` 是可信 repository 接口，不是对任意代码的沙箱。禁止手动 Commit/Rollback、建立独立写事务、保存 Tx 到回调外或执行网络发送。框架拒绝嵌套根事务，但不能阻止恶意回调直接调用底层连接。外部密钥/桶/MQ 不应在短事务持锁时调用；需要的准备和清理由各领域设计。

## 事务、锁与重试

每次尝试先在真正只读事务中按令牌摘要解析当前有效会话与活跃主体，再发现参与者。根写事务按后台主体 UUID、学生账号 UUID 排序锁 guard；后台通过固定 SECURITY DEFINER 函数锁定指定身份行，不授予后台 API 修改身份表能力。随后重读参与集合，变化即回滚重算；不在已有锁后追加更小 UUID。

资源按心愿、申请、匹配、会话、审核任务、消息的固定顺序，再按 UUID 锁行；锁后再次重读完整集合。此协议要求所有领域写入口遵守相同 guard 和锁序，Discover 返回所有可能受影响的主体。回调不能先锁发件箱再反向取得业务锁。后台角色变更、处罚、注销、会话撤销也须先锁相关主体 guard；直接绕过协议的运维 SQL 不受业务并发保证保护。

取得全部锁后读取 PostgreSQL 时间，复核会话/权限，再处理幂等与业务版本。40001、40P01、55P03、参与集合变化及版本冲突最多重试配置次数，保持原请求和客户端期望值。总 context 超时和每次 lock_timeout 限制等待。达到上限返回稳定冲突/重试错误，不忙等无限重试；其他驱动错误屏蔽原文并失败关闭。失败或 panic 回滚业务和回执，成功完成日志只在根事务提交后输出。

`internal/identity.Store` 目前先取身份全局 advisory lock 再锁账号，不能直接在已持账号 guard 的回调中调用；后续身份领域接线须统一资源顺序与当前事务 repository，避免逆序或独立提交。

## 当前授权与并发字段

学生会话按 SHA-256 摘要读取数据库，锁后重新校验主体、auth_epoch、撤销及到期时间、账号生命周期。Verified 额外要求当前 verified；Ordinary/Verified 拒绝当前 mute/ban，warning 不限制交互。Restricted 仅供服务端指定的申诉、警告、隐私等受限入口，仍要求有效会话与活跃主体，不能由客户端选择。

后台独立会话按当前 admin_accounts 状态/代次和 admin_role_bindings 精确角色白名单授权，不隐含 super_admin 可绕过所有角色要求。会话表既有 RLS 继续隔离学生与后台。Redis 不参与本库的权限判定或锁；Redis 故障不能令本库绕过数据库检查。网关限流、Redis 失效时入口收敛、缓存清理尚未装配，不宣称已完成这些故障路径。

| 协议字段 | 允许绑定的已锁对象 |
| --- | --- |
| expected_version | 账号、心愿、申请、消息的 version |
| wish_expected_version | 心愿 version |
| expected_write_epoch | 会话 write_epoch |

一个字段名或对象不能重复断言，正整数版本不自动刷新。匹配和审核任务目前仅支持锁行，表无通用 version；后台账号 version、其他聚合版本及领域语义须在后续 repository 扩展，不能用零值或会话代次冒充。资源白名单不代表每个运行权限组都有写锁权：PostgreSQL FOR UPDATE 需要 UPDATE 权限，调用方必须使用经批准的领域权限配置；本批不为尚未实现的审核/取消业务扩大表权限，拒绝时不降级成无锁读取。

## 幂等与数据边界

回执范围为当前数据库主体命名空间/ID、HTTP 方法、规范资源路径和幂等键 SHA-256。请求摘要包含服务端命令名、已验证类型化 DTO 和排序后的期望版本；Go JSON 编码提供 map 键稳定顺序，不是任意原始 JSON 的通用规范化器。处理器必须先统一可选字段、数值及路径语义，不可把未校验 RawMessage 当规范 DTO。摘要不是匿名化保证，不得索引或记录摘要和原文。

同键同摘要只返回结果 UUID；不同摘要冲突。重放仍执行当前会话、当前角色/资格和 Authorize/Resolve；跳过首次版本相等检查，因为原命令可能已推进自身版本。对象被删除或当前不可访问时，不返回旧正文。过期回执在同一主体 guard 内更新 request_hash/result_ref/expires_at；不会删除有效回执。客户端超时后的重试沿用原键和请求。

回执与业务结果同事务持久化，不发送 MQ。API/后台回执 UPDATE 只授三个更新列；权限脚本显式撤销历史列 ACL，防止 table REVOKE 遗漏。后台 guard 函数使用固定 search_path、全限定表、迁移组 owner、仅后台组 EXECUTE；学生/公共组无权调用。已有版本 SQL/表字段注释未改写；新增函数包含中文数据库注释。管理员在显式迁移后执行 `bin/migrate permissions`，普通启动不隐式安装函数或授权。空库 down 后角色与权限辅助函数保留；表不存在时函数不能返回身份，重建后仍应显式重放 permissions。

完成日志包含受控命令名、request_id（安全字符）、duration、attempts、result、稳定 code、recovered，不记录 token、幂等键、请求正文、主体 ID、数据库或 panic 原文。技术日志不替代业务审计或 D05 删除日志。

## 验证与接线限制

单元测试运行 `make check`；真实测试运行 `python3 scripts/check-migrations.py --container`，在随机专用 PostgreSQL 容器的 commands 数据库构造合成账号/会话/处罚，校验真实事务、锁等待及 SET ROLE 权限。未配置 APP_COMMAND_TEST_DSN 时集成用例明确跳过；常规无中间件检查不能替代真实验证。脚本也在锁定 Go 1.25 builder 中离线测试本库，CI 原迁移 job 自动覆盖新增包；远端 CI 未执行。

会话签发/真实身份提供方、HTTP 错误映射、三条额度/B01、实际匹配/聊天/审核/处罚命令、发件箱消费与恢复删除均未在本批实现。真实 D02/D03/D05 和两端验收缺口仍保留在[交付清单](dependency-deliverables.md)。

## 后台工作复用

`NormalizePlan` 与 `LockPlan` 供可信内部消费事务复用完整集合、排序锁和快照；LockPlan 拒绝根连接，不注入请求主体，Tx.Actor 为空，不执行 Bearer 或领域权限判断。消费入口必须重发现参与者、锁定工作源，再由领域回调复核当前资格/版本与隐私条件，同事务写结果/终态/回执。领域 worker 通过显式 permissions 的 lock_command_account 函数取得账号 guard，不获得账号 UPDATE；该函数与后台 guard 同样定参、固定 search_path、最小 EXECUTE，不改变表字段或已应用迁移。普通命令也使用该账号函数，因此迁移后需显式重放 permissions。
